Every stateful service in the uslab-eng-01 namespace is copied nightly to an off-cluster MinIO store — databases as consistent logical dumps, file volumes as incremental, deduplicated, encrypted snapshots. This is how the data flows, how versions are kept, and how to run a backup by hand.

Mechanics

Two methods, by data type

A raw file-copy of a running database can restore into a broken state, so databases get a logical dump. Everything else is plain files — perfect for restic.

Databases

CronJob · pg_dumpall → MinIO
  • An init container drops the mc client into the dump pod.
  • pg_dumpall | gzip | mc pipe streams straight to MinIO — no temp disk.
  • Lands as a date-stamped .sql.gz object you can browse in the console.
  • Full dump every run (not incremental) — simplest, always-restorable.

File volumes

VolSync · restic · copyMethod Direct
  • A mover reads the live PVC on its own node (Direct — TopoLVM can't snapshot).
  • restic uploads only changed blocks, deduplicated and encrypted.
  • Runs as root so every file is readable; trusts MinIO via a custom CA.
  • Each run writes one dated snapshot — a complete restore point.

On demand

Trigger a backup manually, any time

The nightly schedule runs itself — but you can fire a backup whenever you need one.

One rule: never manually trigger a backup that's already running. restic allows a single writer per repo, so overlapping runs cause a stale-lock retry loop.

  1. A single file backup — incremental

    # names: krista-ai-server-backup | shared-mediadb-backup | elasticsearch-backup
#        node1-accesspoint3-backup | node2-accesspoint3-backup
kubectl -n uslab-eng-01 patch replicationsource <name> \
  --type merge -p "{\"spec\":{\"trigger\":{\"manual\":\"run-$(date +%s)\"}}}"

  2. Restore its daily schedule afterward

    # the manual trigger replaces the schedule until you remove it
kubectl -n uslab-eng-01 patch replicationsource <name> \
  --type json -p '[{"op":"remove","path":"/spec/trigger/manual"}]'

  3. A single Postgres dump — full, dated, no cleanup

    # inst: global | node1 | node2
kubectl -n uslab-eng-01 create job --from=cronjob/pgdump-<inst> pgdump-<inst>-now-$(date +%s)

  4. Everything at once

    TS=$(date +%s)
# 5 file backups
for rs in krista-ai-server-backup shared-mediadb-backup elasticsearch-backup \
          node1-accesspoint3-backup node2-accesspoint3-backup; do
  kubectl -n uslab-eng-01 patch replicationsource "$rs" \
    --type merge -p "{\"spec\":{\"trigger\":{\"manual\":\"all-$TS\"}}}"
done
# 3 database dumps
for i in global node1 node2; do
  kubectl -n uslab-eng-01 create job --from=cronjob/pgdump-$i pgdump-$i-now-$TS
done
# then run step 02 on the 5 sources to restore their schedules
